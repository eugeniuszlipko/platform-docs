## Критерии, добавленные при оценке

Откатываемость истории; сдвиг серьёзности находок (структурные до кода или граничные после); дефекты, дошедшие до владельца, на фазу; передача между чатами (impl-план + ledger); стоимость в токенах (на фазу, на 1k строк, на тест); нагрузка на владельца (число реплик: B 16 и 24, C 13 / 14 / 18 / 23); избыточность ревью (число субагентов, пересечение находок); видимые дефекты мобильной вёрстки. Итог: C лучше по откатываемости, сдвигу находок, дефектам владельцу и передаче; B лучше по чистоте зелёных e2e и избыточности ревью; стоимость различается на 12–17%, на тест C дешевле.

## Решения 2026-10-18 (новые правила, период D)

1. **Один этап фазы — один чат:** «Планируем фазу N» → «Начинаем фазу N» → «Принимаем фазу N». Цель: контекст около 200k. → `meta-planning` §5.
2. **Impl-план только для миграций/RLS или двух репозиториев**; `brainstorming` пропускать при утверждённой спеке. → `superpowers-routing` §3.
3. **Владелец не читает документы**: только ключевые вопросы, краткое резюме в чате, чек-лист приёмки в чат. → `meta-planning` §3a.
4. **Один ревьюер на слой**, один запуск типа на репозиторий за фазу. → `skills/ecc/README.md` «Ревьюеры по слоям».
5. **Проверка на телефоне 390 px в каждом визуальном срезе.** → `testing.md` «Проверка на телефоне».
6. **e2e не зависят от живых данных**; накопленный долг — [B-007](../backlog/B-007-e2e-decouple-from-live-data.md). → `testing.md` «e2e и живые данные».

## Ограничения

Две фазы против четырёх разной сложности; Superpowers, `meta-planning` и накопленный опыт проекта неотделимы; веса цены условные; метрики кода считались по файлам, добавленным или изменённым в фазе, на текущем main; классификация правок владельца выполнена по сообщениям в чате и субъективна; период A в токенах не оценён. Число находок ревьюеров по уровням серьёзности не приводится: разбор отчётов машиной оказался ненадёжным (форматы разные, отчёты фонового режима приходят «рукопожатием»).
