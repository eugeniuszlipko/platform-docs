## Цель и границы

**Цель.** Живые формы подписки (Home, Articles, About + окно), приём адресов и сообщений Contact с серверной проверкой Turnstile, разделы Subscribers и Messages в админке, редактируемые тексты Contact и настройки окна.
**Не входит:** отправка писем (подписчикам и уведомления), double opt-in, ссылка отписки, ответы из админки, имя/IP подписчика и отправителя, антиспам кроме Turnstile, cookie-согласие/GA (Фаза 8; но флаг окна в `localStorage` учесть в Privacy там).
**Анти-цели:** публично читаемые/записываемые через anon-ключ таблицы `subscribers`/`messages`; раскрытие, есть ли адрес в списке; потеря введённого при ошибке; «успех» при сбое проверки Turnstile или записи; навязчивое окно (повтор после закрытия раньше срока, на legal/Contact, до 2-го перехода); ловушка фокуса без выхода; сообщение, потерянное молча.

## БД (миграции в `urban.gardener/supabase/migrations/`, применение через Supabase MCP, проект `base-one`)

Общее: схема `urban_gardener`; **явный `revoke all … from anon, authenticated`** на каждую новую таблицу (в схемах по умолчанию anon получает select на новые таблицы), затем точечные `grant`; RLS включён; публичных политик нет; запись только `service_role` (сервер после Turnstile). Проверка под ролями (метод — Фазы 3/6): anon не читает/не пишет/не удаляет; authenticated не-админ — 0 строк; admin читает/меняет/удаляет; `has_table_privilege('anon', …)`; `get_advisors`; ревью `database-reviewer`.

- **0025_subscribers.sql** — как avocado `0018` (читать): `subscribers(id uuid pk default gen_random_uuid(), email text not null unique, created_at timestamptz not null default now())` + CHECK `email = lower(email)`, формат `^[^\s@]+@[^\s@]+\.[^\s@]+$`, `char_length ≤ 254`. Права: `grant select, delete to authenticated`, `grant all to service_role`; политики «Admin read subscribers» (select) и «Admin delete subscribers» (delete) с `public.is_admin()`.
- **0026_messages.sql** — `messages(id uuid pk, name text not null, email text not null, subject text, message text not null, is_read boolean not null default false, created_at timestamptz not null default now())`; CHECK: `btrim(name) <> ''`, `char_length(name) ≤ 120`, формат e-mail, `char_length(email) ≤ 254`, `char_length(subject) ≤ 200`, `btrim(message) <> ''`, `char_length(message) ≤ 2000`; индекс `(is_read, created_at desc)`. Права: `grant select, update (is_read), delete to authenticated` (column-level update только `is_read` — урок cozycorner column-level grants), `grant all to service_role`; политики Admin select/update/delete через `public.is_admin()`. Без IP.
- **0027_contact_page.sql** — страница Contact редактируется в админке по образцу About (Phase 5): **вставить** строку `pages.slug = 'contact'` (её нет: 0018 сидирует только about/privacy/terms; проверить CHECK/список допустимых slug у `pages` и расширить; SEO + шапка `hero_eyebrow/hero_title/hero_description` уже есть у `pages` — использовать) и singleton `contact_content` (карточки: `email_title, email_text` (адрес карточки «Email us» **не хранится здесь**: берётся из `site_settings.contact_email` — один источник для Privacy/Terms/Contact/текста ошибки формы); `partners_title, partners_text, partners_address; where_title, where_text; social_title, social_text; form_title, form_hint`), CHECK-и не пустых строк и формата адресов (`mailto`-безопасно: как правила e-mail Phase 5), **сид = текст референса**; права как у `about_content` (anon select под RLS «Public read»; запись admin). RPC `save_contact_page(p_page_id, p_page, p_contact) → jsonb` по шаблону `save_about_page` (0019/0020: security invoker, `search_path=''`, неизвестный ключ → `22023`, формат → `23514`, нет строки/не админ → `P0002`, `where true`-обновления из-за safeupdate). **Настройки окна:** в `site_settings` добавить `newsletter_popup_enabled boolean not null default true` и `newsletter_popup_days int not null default 30 check (between 1 and 365)`; `save_site_settings` принимает новые ключи (`create or replace`, как 0021; булев тип — отдельная ветка проверки типов: текущая проверка «каждое поле — текст или null» не подходит, расширить аккуратно и покрыть тестами SQL).
Нумерацию можно разбить на 0027/0028 (контакт / настройки окна) — по месту.

## Сайт (`urban.gardener`)

**Серверное:** `lib/supabase/service.ts` (`import 'server-only'`, env `NEXT_PUBLIC_SUPABASE_URL` + `SUPABASE_SECRET_KEY`, схема `urban_gardener`); `lib/turnstile.ts` — `verifyTurnstile(token, ip)` (`TURNSTILE_SECRET_KEY`, siteverify, `remoteip` из `x-forwarded-for`, fetch с таймаутом ~8 с; сетевая ошибка/таймаут → отдельный результат «недоступно», **не успех**); `lib/forms-validation.ts` — чистая логика (`normalizeEmail`, `isEmail`, `validateContact`) — **тесты red-first**, общая для клиента и сервера.
**`app/api/newsletter/route.ts`** (Route Handler, `nodejs`, `force-dynamic`) — порт avocado: тело `{ email, token }`; битый JSON/типы → 400; email нормализуется (trim+lower, ≤ 254) и проверяется → 400; нет токена → 403; Turnstile fail → 403; Turnstile недоступен → 503; insert; `23505` → `{ ok: true }` (идемпотентно, без раскрытия); иное → 500 + `console.error`; ответы без деталей.
**`app/api/contact/route.ts`** — то же для сообщений: `{ name, email, subject?, message, token }`; серверная валидация теми же правилами (обрезка пробелов, длины, формат e-mail), Turnstile, insert в `messages`; успех `{ ok: true }`; ошибки как выше. Не логировать тело сообщения (персональные данные).
**Env:** `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`, `SUPABASE_SECRET_KEY` — Vercel (production + preview); локально — тестовые ключи Cloudflare (site `1x00000000000000000000AA`, secret `1x0000000000000000000000000000000AA`); имена перечислить в AGENTS.md. Блоки серверные, клиентский остров — форма.
**Окно `NewsletterModal`** (клиент; монтируется в `app/layout.tsx`, настройки `enabled`/`days` приходят пропсами из уже загружаемых `site_settings`): счётчик просмотров в **`sessionStorage` (на вкладку; перезагрузка его не сбрасывает)**, увеличивается при каждой смене `usePathname` (первый просмотр, в т.ч. заход прямо на `/contact`, `/privacy`, `/terms`, = 1; повтор того же пути не считается); **показ — на первом разрешённом пути при счётчике ≥ 2** через 500 мс (то есть исключённые пути считаются просмотрами, но окно на них не появляется); не на `/contact`, `/privacy`, `/terms`; не пока открыта панель поиска/меню (отложить/закрыть их); флаг в `localStorage` (try/catch): `{ shownAt }` — показывать не чаще раза в `days` суток; после успешной подписки — `{ subscribed: true }` (не показывать); `enabled = false` → не монтировать. ## Подводные камни

- Turnstile не работает на `localhost` с боевым ключом (память «avocado turnstile localhost») → тестовые ключи; на `*.vercel.app` хост должен быть в списке виджета; при подключении боевого домена добавить его.
- Токен Turnstile одноразовый: после любой попытки перемонтировать виджет (иначе вторая отправка → 403); один виджет на странице — два блока (форма + окно) не должны конфликтовать (раздельные экземпляры/`key`).
- `SUPABASE_SECRET_KEY` без `NEXT_PUBLIC_`, `server-only`; не выводить значение; при переносе из Vercel Avocado — через CLI напрямую между проектами, без записи в файл.
- Дубль адреса не выдаёт «такой адрес уже есть».
- Окно и `template.tsx` (fade): счётчик считать по `usePathname`; layout статичен (ISR) — никаких `cookies()/headers()`; настройки окна приходят из `site_settings` (обновляются через ≤ 60 с).
- Column-level grant у `messages` (только `is_read`), иначе админ-сессия сможет править текст сообщений; проверить под ролью `authenticated` админа.
- Расширение `save_site_settings` булевым ключом: текущая валидация «поле — текст или null» (0019/0021) нужно обновить без регрессии для остальных ключей.
- Тест-алиас: `vi.mock('@/lib/…')` по алиасу в тестах не срабатывает — относительные пути; `userEvent` с fake timers — `jest.advanceTimersByTime`-заглушка (как в `HeaderSearch.test.tsx`).
- Персональные данные в `messages`: не логировать тело, не отдавать анону; срок хранения — вопрос владельцу к запуску (чек-лист).
